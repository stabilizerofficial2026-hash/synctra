# SyncTrA Phase 8C — Private Social Connections

This package adds private in-app social features to the Phase 8A/8B premium interface.

## Included
- Notifications panel (new follower, direct message, in-app post share, post reaction and comment).
- One-to-one private messaging.
- Share post privately with another SyncTrA member by username. No external links or public share URLs.
- Followers and Following lists with unfollow controls.
- Follower counts.
- Database notifications are generated by activity triggers.

## Database migration
The migrations `synctra_private_social_features`, `secure_synctra_activity_notifications`, and `synctra_follow_network_read_access` have been applied to the linked Supabase project. They create `direct_messages` and `post_shares`, add participant-only RLS policies, add a safe activity notification trigger, and allow members to read only their own incoming/outgoing follow relationships. Existing `follows` and `notifications` tables are reused.

## Deployment
1. Back up your current GitHub commit.
2. Extract this ZIP.
3. Replace the four root files in the GitHub repository with these files.
4. Commit and wait for Cloudflare Pages.
5. Test with two separate member accounts:
   - Account A follows Account B; B should receive a notification.
   - A sends B a private message; only A and B should see the conversation.
   - A shares a post with B; B should receive a notification.
   - Confirm follower counts and unfollow.
   - Like/comment on a post and verify its owner gets a notification.

## Important privacy
Direct messages and post shares are restricted to participants by RLS. Blocking either direction prevents new direct messages and post shares. Do not disable RLS or expose service-role keys.

## GIF profile/cover
The profiles table already contains avatar_asset_id and cover_asset_id, linked to generated_assets. The media generation provider is not yet connected. This phase does not pretend GIF generation is active. The next media phase should create animated GIF assets inside SyncTrA and then allow selecting those generated assets as avatar/cover. GIF playback support is browser-native once a real generated GIF asset is available.
